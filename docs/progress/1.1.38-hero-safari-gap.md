# 1.1.38 — Home hero: huge empty gap under the portrait on real iOS

**Status:** ✅ shipped

## Symptom
On production, on a real iPhone, the home hero showed the doctors photo and then
roughly a full screen of empty indigo before the "بالأرقام" stats section. In
Chrome DevTools device emulation the same page looked correct — which is exactly
why it survived review.

## Root cause
`.hero-indigo__portrait-wrap` carried `min-block-size: 100%`. It is a **grid
item** in `.hero-indigo__grid`, which uses `align-items: center`, so the item is
never stretched and its containing block height is indefinite.

A percentage `min-height` against an indefinite containing block is a genuine
engine divergence:

- **Blink** treats it as `auto` → wrapper is content-height → looks right.
- **WebKit** resolves it against the grid container's used block size → on the
  stacked one-column mobile layout that is the height of the *whole* hero
  (copy + photo), so the wrapper inflated to roughly double the photo, and the
  extra height rendered as blank indigo underneath it.

So the emulator was never going to show this. Reproduced deterministically in
the iOS Simulator (iPhone 17, Safari/WebKit) against the local dev server, and
fixed there.

The declaration had no job to do in the first place: the portrait sizes itself
with `aspect-ratio: 4 / 5`, and the wrapper only exists to be a positioning
context.

## Fix
Deleted the one line.

## Files
- `src/components/Home/HeroIndigo.vue` — dropped `min-block-size: 100%` from
  `.hero-indigo__portrait-wrap`.

## Verification
- iOS Simulator, iPhone 17, real WebKit: gap reproduced before, gone after; the
  hero now ends just below the photo and flows straight into `StatsWedges`.
- Chromium at 1440px: two-column layout unchanged — grid still `580/475`, the
  portrait still hangs its intentional 60px past the section edge
  (`portrait 611px` vs `wrap 534px`).
- Chromium at 599px: wrapper is content-height (`wrap 525px` /
  `portrait 531px`).
- `tsc --noEmit` exit 0 · `codegen:check` no drift · `quasar build -m spa`
  succeeded.

## Note
Two other `min-height: 100%` declarations exist (`CertificatePage.vue`,
`ClassroomQA.vue`). Both are page roots in normal block flow, not grid items
under `align-items: center`, so they resolve identically in both engines and
were left alone.
