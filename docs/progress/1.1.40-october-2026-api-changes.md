# 1.1.40 — October 2026 backend API changes (frontend adaptation)

- **Date:** 2026-10-18
- **Status:** ✅ done (verified end-to-end against the backend at `56d0e35`, run locally)
- **Plan:** `../../../docs/superpowers/plans/2026-10-18-frontend-api-changes-2026-10.md`
- **Spec:** `../../../frontend-api-changes-2026-10.md` (backend release note, 18 Oct version)

## What changed (this repo)

- Dropped PayPal, Braintree, SmartNode and SyberPay components, query documents,
  store state and type aliases; `PaymentProvider` is now `'stripe' | 'bankak'`.
- `codegen.yml` schema URL is overridable with `GRAPHQL_SCHEMA_URL` (production
  stays the default; the new schema was generated from the local backend).
- `src/utils/graphqlErrors.ts`: one parser for the four payload/top-level error
  shapes (bare `{message}`, `{field:[{message}]}`, list of `{message}`, list of
  single-key objects such as `[{stripe: "…"}]`, and `nonFieldErrors` wrapping).
- `src/utils/stripe.ts`: `stripeKeyFromPayload` (null → no card; accepts the
  object and the JSON-string form) and `loadStripeJs` (Stripe.js is injected
  only when a key exists). `payment.vue` shows the card option only then.
- `afilliateBord.vue`: `joinPyramidProgram` is single-flight; `success: true`
  (new or existing account) stores `instance.pyramidCode`; "Pyramid Affiliate
  Does Not Exist" routes to the registration-code page.
- `RegisterationCode.vue` + `src/utils/joinPlatform.ts`: `joinPlatform` sent
  once per action; "Already exists" is treated as registered; a bad code keeps
  the wrong-code text; other failures show the server message.
- `bankakPay.vue` and `ClassroomOverviewPanel.vue` show payload messages
  verbatim ("Order not found", "User has no valid enrollment …").

## Ten-persona error-visibility run (local backend, Celery inline)

Seeded `p1@e2e.test` … `p10@e2e.test` with distinct states and drove the API
matrix (`matrix.py`) plus the browser for the user-facing ones.

| Persona | State | Backend answer | What the user sees |
|---|---|---|---|
| P1 | normal | order + upload `success:true` | Full UI flow (cart → profile → Bankak → real file upload) lands on "تم استلام طلبك" |
| P2 | no registration code | `checkPyramidAffiliate` → "PyramidAffiliate matching query does not exist." | Router gate sends them to the registration-code page (note: the backend still accepts an order from a no-code user; the gate is client-side) |
| P3 | enrolled after adding to cart | top-level "User already has valid enrollment in the course ..." | Was a generic "تعذّر إنشاء الطلب" toast → fixed in `e3bafe7`; now shows "لديك اشتراك مسبق في أحد الكورسات…" |
| P4 | uploads to another user's order | `{message: "Order not found"}` | Not reachable from the UI (own orders only); message would be shown verbatim |
| P5 | `joinPlatform` twice | second call "Already exists" (sequential run; SQLite cannot reproduce the concurrent lock) | Treated as registered |
| P6 | never referred, `joinPyramidProgram` | `{message: "Pyramid Affiliate Does Not Exist"}` | Notified and routed to the registration-code page |
| P7 | wrong code, then right code | "Pyramid matching query does not exist." / success | Inline "هذا الكود غير صحيح — يرجى التحقق والمحاولة مجدداً." then redirect to the intended page |
| P8 | unverified account | `nonFieldErrors[{message: "Please verify your account.", code: "not_verified"}]` | Login lands on the "activation link sent" page; cart actions bounce to login |
| P9 | re-upload another user's receipt | top-level "AttachmentTransaction matching query does not exist." (spec says payload "Not Found") | Re-upload UI is not mounted anywhere (orphan component) |
| P10 | certificate on another enrollment | `{message: "User has no valid enrollment ..."}` | Shown verbatim in the classroom certificate panel |
| Manager | approve the same receipt twice | success, then "Already approved" | "finished", then info "This receipt was already approved" |
| Instructor | pool queries / `allEnrollments` | "You do not have permission to perform this action" | Panels hidden; "Staff only" banner; no enrollments tab |

## Open items for the backend team

- Non-staff pyramid managers get "Access denied" on `order.user.{username,
  email, phoneNumber2, phoneNumber3}` inside `allPyramidAttachmentTransactions`,
  which nulls every node. The guard predates the October merge
  (`security/types_security.py`); the dashboard now shows the error instead of
  an endless skeleton, but managers cannot review receipts until it is relaxed.
- `createStripeCheckout` requires `successUrl` and `cancelUrl` even though the
  schema marks them optional (resolver raises when omitted). The frontend always
  passes both.
