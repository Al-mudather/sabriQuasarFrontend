# 1.1.40 — October 2026 backend API changes (frontend adaptation)

- **Date:** 2026-10-18
- **Status:** ✅ done (verified end-to-end against the backend at `56d0e35`, run locally)
- **Plan:** `../../../docs/superpowers/plans/2026-10-18-frontend-api-changes-2026-10.md`
- **Spec:** `../../../frontend-api-changes-2026-10.md` (backend release note, 18 Oct version)

## What changed (this repo)

- Dropped PayPal, Braintree, SmartNode and SyberPay components, query documents,
  store state and type aliases; `PaymentProvider` is now `'stripe' | 'bankak'`.
- `codegen.yml` schema URL is overridable with `GRAPHQL_SCHEMA_URL` (production
  stays the default; the new schema was generated from the local backend).
- `src/utils/graphqlErrors.ts`: one parser for the four payload/top-level error
  shapes (bare `{message}`, `{field:[{message}]}`, list of `{message}`, list of
  single-key objects such as `[{stripe: "…"}]`, and `nonFieldErrors` wrapping).
- `src/utils/stripe.ts`: `stripeKeyFromPayload` (null → no card; accepts the
  object and the JSON-string form) and `loadStripeJs` (Stripe.js is injected
  only when a key exists). `payment.vue` shows the card option only then.
- `afilliateBord.vue`: `joinPyramidProgram` is single-flight; `success: true`
  (new or existing account) stores `instance.pyramidCode`; "Pyramid Affiliate
  Does Not Exist" routes to the registration-code page.
- `RegisterationCode.vue` + `src/utils/joinPlatform.ts`: `joinPlatform` sent
  once per action; "Already exists" is treated as registered; a bad code keeps
  the wrong-code text; other failures show the server message.
- `bankakPay.vue` and `ClassroomOverviewPanel.vue` show payload messages
  verbatim ("Order not found", "User has no valid enrollment …").

## Open items for the backend team

- Non-staff pyramid managers get "Access denied" on `order.user.{username,
  email, phoneNumber2, phoneNumber3}` inside `allPyramidAttachmentTransactions`,
  which nulls every node. The guard predates the October merge
  (`security/types_security.py`); the dashboard now shows the error instead of
  an endless skeleton, but managers cannot review receipts until it is relaxed.
- `createStripeCheckout` requires `successUrl` and `cancelUrl` even though the
  schema marks them optional (resolver raises when omitted). The frontend always
  passes both.
