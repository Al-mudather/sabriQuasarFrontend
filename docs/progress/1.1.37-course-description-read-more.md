# 1.1.37 — Course details: the description's "read more" never appeared

**Status:** ✅ shipped

## Symptom
On `/#/course/...` most of the description was clamped away with a fade and **no
way to expand it**. Reported with the MRCP 1 course, where 8 of ~26 rendered
lines were visible. Same on desktop and mobile.

## Root cause
Two independent failures in `aboutTheCourse.vue`'s hand-rolled clamp, and the
toggle needed *either* to fire:

1. `measure()` read `proseEl.value` **synchronously** and bailed out on `null`.
   It was called from `onMounted` (brief not fetched yet → `v-if` false → no
   element) and from a default `flush: 'pre'` watcher on `courseData.brief`
   (fires *before* the DOM renders the element). So on the only render that
   matters — the one where the GraphQL brief arrives — `needsClamp` stayed
   `false` forever.
2. The fallback was a character-count heuristic: `plainBrief.length > 480`. A
   brief written as many short bullet lines never trips it. The MRCP brief is
   **453 plaintext characters over ~26 rendered lines**.

Measured on the live dev server before the fix:

| viewport | content height | visible | toggle |
|---|---|---|---|
| desktop | 769px | 237px | absent |
| 375px   | 626px | 237px | absent |

## Fix
Replaced the bespoke clamp with the page's existing `ReadMore.vue`, which
already measures `scrollHeight` under a `ResizeObserver` — correct whenever the
content arrives, and no character heuristics. It is what the two sibling
sections (`whatIwillLearn`, `coursePreRequisites`) already use, so the toggle
now looks and behaves identically down the page.

Also:
- Clamp raised from 8 lines (237px) to **340px** (~11 Arabic lines). The
  description is the page's primary copy, so it gets a taller budget than the
  260/300px sibling rails.
- Dropped `display: -webkit-box` + `-webkit-line-clamp`, which fought the
  `max-block-size` and collapsed the brief's `<p>` margins. `ReadMore` clamps
  with `max-block-size` alone.
- Hardened the `v-html` prose for small screens — the brief is author-entered
  HTML: `img { max-inline-size: 100% }`, `overflow-wrap: break-word` for long
  exam codes/URLs, and `table`/`pre` scroll inside themselves. Previously an
  author-pasted wide element could push a horizontal scrollbar onto a 375px
  viewport.

## Files
- `src/components/courseDetails/aboutTheCourse.vue` — rewritten around
  `ReadMore`; ~60 lines of broken measurement logic removed.

## Verification
Live on the dev server, both viewports:

| viewport | clamped | expanded | toggle |

| desktop | 340px | 769px | عرض المزيد ⇄ عرض أقل |
| 375px   | 340px | 626px | عرض المزيد ⇄ عرض أقل |

`document.documentElement.scrollWidth > innerWidth` is `false` at 375px — no
