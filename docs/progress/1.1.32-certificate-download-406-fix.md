# 1.1.32 — Fix: no user could download any certificate

**Status:** ✅ shipped (verified live — a real download succeeded after the fix)

## Symptom
Users reported they could not download **any** certificate. On `/Certificates`
the button often rendered greyed out; where it was clickable, nothing arrived.

## Root cause — three separate blockers stacked

### 1. `Accept: application/pdf` → HTTP 406 (the real one)
The download request sent `Accept: application/pdf`. The endpoint is Django REST
Framework and has **no `application/pdf` renderer registered**, so content
negotiation rejects the request with `406 Not Acceptable` — *before*
authentication even runs. Probed directly:

| `Accept` | Response |
|---|---|
| `application/pdf` | **406 Not Acceptable** |
| `*/*` | 401 (auth reached) |
| `application/json` | 401 (auth reached) |

Confirmed in the dev log for three different certificates:

```
[certificates] download failed {"pk":3635,"status":406,"statusText":"Not Acceptable"}
```

Fix: send `Accept: '*/*'`. Nothing backend-side needed.

### 2. `:disabled="!isDownloadable(cert)"` on `/Certificates`
Any certificate the backend returned with `isPrintable: false` rendered a
greyed-out, unclickable button. Removed, along with the `isDownloadable` /
`downloadBlockedReason` helpers and the "قيد المراجعة" note.

### 3. `certificateName` gate aborted the click and redirected
If `user.certificateName` was empty the handler bailed out and pushed the user
to `/profile` — so the button looked dead for anyone whose cached user object
lacked the field. The download now always attempts; the "set your certificate
name" warning + profile redirect fire only if the **server** rejects it.

## Also fixed: the classroom certificate card was a stub
`src/components/classroom/certificate/CertificateCard.vue` gated on
`canDownload = isPrintable && pdfUrl !== null`, where `pdfUrl` read
`node.pdfUrl ?? node.pdf ?? node.fileUrl` — **none of which exist on
`CertificateNode`**. `pdfUrl` was therefore always `null`, so the button was
permanently disabled for every user and `onDownload()` returned early anyway.

Wired it to the same authenticated endpoint the main page uses
(`GET /api/enrollment/certificate/download/:pk` with the JWT, blob →
`exportFile`), with a loading state and matching error toast. The neighbouring
share button was dead for the same reason — it now shares the page URL.

## Verification
- `vue-tsc` clean for both touched files (project baseline errors elsewhere are
  pre-existing and untouched).
- `quasar build -m spa` green.
- Live: a real download succeeded through the dev server.
