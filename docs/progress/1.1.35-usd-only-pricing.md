# 1.1.35 — USD-only pricing: drop SDG display + remove the currency switcher

**Status:** ✅ shipped

## Request
Each course carries two prices — SDG (Sudanese pound) and USD. The UI showed
SDG. Show **only** the dollar price, and remove the currency switcher since
payment is now unified on one currency. Priority surfaces: the course card and
the cart/checkout cards.

## What changed conceptually
Display currency stopped being a *user preference* and became a *constant*.

Before: `settings.currency` (Pinia, default `'SDG'`, **persisted**) was read by
8 components; a dropdown (`components/Home/Currency.vue`) and the three login
handlers wrote to it; each price surface indexed the course's pricing map with
whatever that field happened to hold, with per-file fallbacks that disagreed
(`'SDG'` in `courseCard`, `'SAR'` in `CategorySection` and `CourseDetails`).

After: one constant in `src/utils/currency.ts`.

```ts
export const DISPLAY_CURRENCY = 'USD' as const
export function usdPriceOf (map: PriceMap | null | undefined): number | null
```

`CourseNode.currency` is still the backend's JSONString map keyed by currency
code (`{"USD": 120, "SDG": 90000, …}`, parsed by the Apollo typePolicy) — we
simply only ever read the USD key. Nothing about the data contract changed.

## Files

**Foundation**
- `src/utils/currency.ts` — **new.** `DISPLAY_CURRENCY`, `DisplayCurrency`,
  `PriceMap`, `usdPriceOf()`. `usdPriceOf` re-parses the value (the backend has
  been observed to encode amounts as strings inside the JSONString) and returns
  `null` — not `0` — when there is no usable price, so callers can tell "not
  priced yet" apart from "free".
- `src/stores/settings.ts` — `currency` state, `updateCurrency`,
  `setCurrencyAction` and `setCurrency` all removed. **`persist.paths` is now
  `['isEnglish']` only, and that is load-bearing:** existing visitors have
  `{"currency":"SDG"}` sitting in `localStorage['settings']`, and leaving the
  key in `paths` would rehydrate that stale preference over the new default.
- `src/types/settings/types.ts` — `CurrencyCode` narrowed to `'USD'`;
  `SettingsState.currency` dropped.
- `src/components/shared/PriceDisplay.vue` — `currency` prop defaults to
  `DISPLAY_CURRENCY` (was `'SAR'`); the SAR/AED glyph map is gone. Renders the
  bare code `USD` rather than `$`, because `$` leading an RTL line reads as
  belonging to the neighbouring Arabic text.

**Course surfaces**
- `src/components/utils/courseCard.vue` — the `/courses` grid card.
- `src/components/Home/CategorySection.vue` — feeds `shared/CourseCard.vue`.
  `onAddToCart` still hands the **raw full pricing map** to the cart, untouched.
- `src/pages/course_management/CourseDetails.vue` — settings store dropped
  entirely (currency was its only reader here).
- `src/components/courseDetails/courseMainCard.vue`.
- `src/pages/course_management/Courses.vue` — deleted a stray `unit="SDG"`
  attribute (the prop was never read by the card).
- The three detail bars (`CourseEnrolSidebar`, `CourseMobileBar`,
  `CourseStickyBar`) needed no change — they forward a `string` prop.

**Cart / checkout**
- `src/components/ShoppingCard/cartCourses.vue`, `payment.vue` — `itemAmount()`
  now uses `usdPriceOf`; the `:currency` binding was dropped from all six
  `PriceDisplay` usages so the component default applies.
- `payment.vue` / `stripPayment.vue` — the Stripe checkout currency was
  hardcoded `'USD'` in one and store-driven in the other; both now pass
  `DISPLAY_CURRENCY`. That divergence is gone.
- `bankakPay.vue` — two `currency === 'SDG' ? … : …` conditionals collapsed to
  the Bankak branch. **Deliberately kept the SDG-branch wording**: this screen
  *is* the Sudanese-bank transfer flow and was always rendering that branch, so
  removing SDG *pricing* must not silently reword the page. The white/green
  receipt callout is about which Bankak app screenshot to attach, not currency,
  and stays.

**Switcher removal**
- `src/components/Home/Currency.vue` **deleted** (already dead — nothing
  imported it), along with its three now-unreferenced assets `exchange.png`,
  `sudan.png`, `united-states .png`.
- `src/i18n/{ar,en}/index.js` — removed the switcher strings
  (`حدد عملة الشراء`, `الجنيه السوداني`, `الدولار الامريكي`,
  `تم تغيير العمله الى:`) plus the orphan `دولار أمريكي`. Each was grepped for
  live call sites first.
- `src/components/Account/{Login,GoogleAuthentication,FacebookAuthentication}.vue`
  — each read `tokenAuth.user.userCurrency` and called `setCurrency`. Removed.
  Post-login navigation in these files is untouched (it has its own bug history:
  1.1.15–1.1.18).

## Bug fixed along the way
`purgeZeroCostItems()` in both `cartCourses.vue` and `payment.vue` dropped a
course from the basket when **either** `courseFee === 0` **or**
`courseFeeInSdg === 0`, behind a "this course is under preparation" toast. With
SDG no longer maintained, a course priced correctly in dollars but carrying no
SDG figure would have been silently purged from the cart. Now gated on
`courseFee` only.

Related: `courseFee` **is** the dollar figure (the schema carries the Sudanese
amount separately as `courseFeeInSdg`), which is why `courseCard`'s fallback to
`courseFee` when the map has no USD key remains correct, and why
`payment.calculateDollarAmount()` was already right to sum it.

## Deliberately left alone
- **Pyramid / marketing payouts are still SDG** — `MyMarketingPage.vue`
  (`payoutCurrency = 'SDG'`), `MyBalance.vue`, `MyPyramidRewards.vue`,
  `MyWithdrawsList.vue`. These are a real payout currency, not a display
  preference (the code says so explicitly). Switching affiliate payouts to USD
  is a **business decision plus a backend change**, not a UI cleanup — flagged,
  not done.
- Orders / transactions (`MyOrdersPage`, `transactionOrderDetail`,
  `TransactionCard`) render the **backend-supplied** `order.currency` /
  `transaction.currency`. Historical orders genuinely were placed in SDG, so
  overriding them to USD would misreport what the customer actually paid.
- `src/types/courses/types.ts` `CurrencyCode` still lists the full union — it
  mirrors the backend's `OrderCurrency` enum and is used to type the raw map.

## Follow-ups
- `userCurrency` is still selected by `LoginUserWithEmail.js`,
  `LoginUserWithUserName.js`, `CreateSocailAuth.js` and `GetMyProfileData.js`
  but is now read by nothing. Dropping it needs a `npm run codegen` run.
- Two i18n keys orphaned by the `bankakPay` simplification:
  `ارفق فاتورة الدفع` and `اضغط للإرفاق فاتورة الدفع`. Also `الريال السعودي`,
  left behind in the (now nearly empty) switcher i18n block.
- Every course must carry a `USD` entry in its pricing map, or the card falls
  back to `courseFee`. Worth an audit on the backend side.
